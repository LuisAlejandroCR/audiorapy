# Memoria del proyecto

## Decisiones

| Fecha | Decisión | Por qué | Alternativa descartada |
|---|---|---|---|
| 2026-10-02 | Monorepo con npm workspaces: `packages/domain`, `apps/api`, `apps/web` | Un solo formato de datos y de cifrado en todas las superficies (reporte §arquitectura) | Repos separados |
| 2026-10-02 | `packages/domain` exporta fuentes `.ts` sin paso de build | Vitest, Vite y `tsx` consumen TS directo; menos piezas que se pueden romper en 68 h | Build con `tsc -b` y referencias de proyecto |
| 2026-10-02 | Vitest + fast-check en lugar de Jest | ESM y TS nativos sin config de transformadores; `--project` cumple "cada carpeta corre sola" | Jest con `ts-jest` |
| 2026-10-02 | API en **Fastify**, no NestJS | El código de Asegura no está en este entorno; Fastify da `inject()` para tests sin red y acceso a los bytes crudos para HMAC. El diseño de ports se mantiene igual, así que portar a NestJS después es mecánico | NestJS portado de Asegura |
| 2026-10-02 | Dashboard en **Vite + React (SPA)**, no Next.js | Todo se descifra en el navegador; no hay SSR que aprovechar y una SPA estática admite una CSP estricta sin excepciones | Next.js |
| 2026-10-02 | Repositorio de citas **en memoria** detrás de un port en esta etapa | La rebanada se demuestra sin credenciales; Postgres entra como adapter (B5) sin tocar el dominio | Postgres desde el día uno |
| 2026-10-02 | B5: `SchedulingStore` asíncrono con dos implementaciones (memoria y Postgres vía `pg`), elegida por `DATABASE_URL`; el esquema se aplica al arrancar y es idempotente | Producción en Postgres estándar; un solo contrato probado contra las dos evita que diverjan | ORM o migraciones versionadas (prematuro para 7 tablas) |
| 2026-10-02 | Dedupe con `INSERT … ON CONFLICT DO NOTHING RETURNING` | Atómico entre réplicas y conexiones: dos entregas simultáneas del mismo id producen un solo efecto | Leer y luego insertar |
| 2026-10-02 | Proveedor de Postgres: **Render Postgres**, no Supabase (pedido del autor) | La API también va en Render y Render es sponsor del reto: un solo host y los créditos del reto. El código usa solo `pg` y SQL estándar, así que cambiar de proveedor es cambiar `DATABASE_URL` | Supabase (descartado por el autor); Neon; Tiger Data |
| 2026-10-02 | Si `DATABASE_URL` está configurada pero la base no responde al arrancar, la API sale con código 1 (`startup.store_unreachable`) | La base es la fuente de verdad: caer a memoria en silencio perdería reservas sin que nadie lo note | Arrancar en memoria |
| 2026-10-02 | Despliegue con un Blueprint de Render (`render.yaml`) y un test que lo ata al código | El archivo no se puede validar contra Render desde la nube (egress bloqueado); el test evita que nombre variables o comandos que no existen | Configurar a mano en el panel |
| 2026-10-02 | "Matar al proveedor" como script reproducible (`npm run demo:degraded`) en CI, no solo como video | Un video prueba una vez; el script prueba cada PR | Solo grabarlo |
| 2026-10-02 | B7: el riesgo vive en un sidecar Python (`services/risk`, FastAPI) con dos modelos: TabPFN-2 y regresión logística como baseline | TabPFN es Python; la API solo habla HTTP y cae a la heurística si el sidecar no responde (3 s) | TabPFN en Node (no existe); `tabpfn-client` (manda datos a Prior Labs) |
| 2026-10-02 | Siempre `ModelVersion.V2` y `tabpfn` fijado en 9.1.0 como extra opcional | Desde 9.x el modelo por defecto es v3.5 (pesos no comerciales); V2 es Apache-2.0 | Usar el modelo por defecto |
| 2026-10-02 | La cifra de TabPFN-2 sale de un workflow manual (`tabpfn-eval`), no de los checks del PR | Hugging Face está bloqueado en la sesión: no se pudo verificar aquí; instalar PyTorch en cada PR cuesta minutos | Exigirlo en cada PR sin haberlo corrido nunca |
| 2026-10-02 | El sidecar recibe 8 rasgos numéricos; `zone` va en 0 hasta que la agenda guarde la zona | Minimización: ni teléfono ni nombre ni datos clínicos; el esquema rechaza campos extra (422) | Mandar el contacto |
| 2026-10-02 | Retención: ids de mensajes procesados 14 días; recordatorios terminados (enviados u omitidos) 30 días tras su vencimiento; purga al arrancar y cada 6 h | Minimización (Ley 1581): lo operativo no se guarda más de lo necesario. 14 días cubre la ventana de reentrega del webhook (supuesto propio: la documentación de Meta no se pudo abrir desde la sesión) | Guardar todo; o borrar también citas (son historia de asistencia y alimentan el riesgo) |
| 2026-10-02 | La purga nunca toca citas, consentimientos ni avisos | La evidencia de consentimiento se conserva; la historia de citas es dato de agenda, no operativo | Purga general por antigüedad |
| 2026-10-02 | Sin doble reserva: restricción de exclusión en Postgres (`tstzrange(starts_at, ends_at) WITH &&` solo para `scheduled`/`confirmed`) y la misma regla en el store en memoria | Una sola terapeuta: dos visitas no pueden solaparse. La base lo garantiza aunque dos pedidos lleguen a la vez; el código solo traduce el error `23P01` a "cupo ocupado" | Revisar antes de insertar (carrera entre leer y escribir) |
| 2026-10-02 | `book()` reprograma en una transacción (cancela la vieja e inserta la nueva); si pierde la carrera, la vieja sigue activa con sus recordatorios | Reprogramar no puede dejar a la familia sin visita | Cancelar primero y luego intentar |
| 2026-10-02 | Si el cupo se ocupó entre la oferta y el toque, el cuidador recibe "Ese cupo se acaba de ocupar" + cupos libres; la conversación vuelve a elegir cupo | Nunca confirmar una reserva que no existe | Mensaje de error genérico |
| 2026-10-02 | El sidecar de riesgo va en Render como **servicio privado** (`pserv`) con el baseline logístico; la API lo encuentra por `fromService … hostport` y `RISK_URL` acepta `host:port` sin esquema | No debe estar expuesto a internet; TabPFN pide PyTorch y queda fuera del despliegue hasta medirlo | Servicio web público; TabPFN en producción sin cifra |
| 2026-10-02 | Tests de Postgres con PGlite (motor real en proceso) + un proyecto `integration` contra un servidor real | PGlite corre en cada `npm test` sin servicios; el servidor real prueba concurrencia y el driver `pg` | Solo dobles; o exigir Docker para `npm test` |
| 2026-10-02 | `AGENTS.md`, `CLAUDE.md` y `docs/` **se commitean** | Las sesiones en la nube clonan el repo limpio: lo gitignored se pierde. `docs/research` ya era público | Gitignorarlos como dice la plantilla |
| 2026-10-02 | Licencia MIT | El reporte pide MIT o Apache-2.0 para el embed del post; MIT es la más corta. Cambiable antes de publicar | Apache-2.0 |
| 2026-10-02 | El consentimiento por chat **solo** cuenta con el botón "Acepto", nunca con texto libre | La autorización debe ser explícita; un "sí" interpretado no lo es | Aceptar `affirm` del clasificador |
| 2026-10-02 | Un texto interpretado como "cancelar" pide confirmación con botones; solo el botón cancela | El LLM clasifica pero no decide; un falso positivo no puede borrar una visita | Cancelar por intención |

## Bitácora

- **2026-10-02** — B1: scaffold, contrato, CI. `npm run verify` verde en local (Node 22.22).
- **2026-10-02** — B2: dominio completo. 17 archivos de test. Dos mutaciones a mano (cancelar por texto; consentir por texto) **no** ponían rojo el primer invariante porque las secuencias aleatorias casi nunca llegaban a `booked`; se reescribió para partir de estados e intenciones arbitrarias y ahora ambas mutaciones fallan.
- **2026-10-02** — B3: API. Primer e2e falló porque el primer cupo quedaba a 24 h exactas y el recordatorio "día anterior" ya era pasado: comportamiento correcto, supuesto del test equivocado. Mutación: quitar el dedupe pone rojo el invariante A2.
- **2026-10-02** — B4: dashboard. Recorrido completo con `playwright-cli` (Chromium 141, emulación móvil 360 px y escritorio 1100 px). Un e2e falló porque `allTextContents()` no espera: leía la lista de palabras antes de que terminara Argon2id; se espera `toHaveCount(24)`.
- **2026-10-02** — B8: arnés `npm run eval:intent`. Línea base de reglas 37/40 (93 %), preferencias 5/5. Fallan tres frases idiomáticas; quedan como señal para medir a Gemma.
- **2026-10-02** — B5: Postgres. La invariante diferencial (memoria vs PGlite) **no** atrapó al principio la mutación "no saltar recordatorios al cancelar": los índices aleatorios casi nunca caían en citas existentes. Con tres citas al inicio de cada secuencia la atrapa 3/3. Misma lección que en B2.
- **2026-10-02** — B9: blueprint de Render + `demo:degraded` (6 escenarios, 22 comprobaciones). Mutación: si el respaldo de reglas devuelve `unknown`, falla "free text still understood by the rules". render.com bloqueado por la red de la sesión: el blueprint queda sin validar contra Render.
- **2026-10-02** — B7: sidecar de riesgo. El invariante de límites (cuerpo de la API ⊂ esquema del sidecar) encontró un bug real: con 500 visitas previas y sin número de sesión, `session_number` salía en 501 y el sidecar habría respondido 422. Corregido. El fuzz de Python marcó dos aserciones demasiado estrictas (infinito no es JSON; 400 es válido), no fallos del servicio. Un proceso de la API huérfano de una corrida fallida respondió en el puerto de la siguiente: la misma lección de `LEARNINGS.md`.
- **2026-10-02** — Retención: `purge(now)` en los dos stores, `markProcessed` recibe la hora. Mutaciones: borrar también recordatorios pendientes (memoria) → falla la invariante de retención; ignorar el estado en Postgres → falla la invariante diferencial 2/2.
- **2026-10-02** — Corrección: los commits de los PR #1–#11 llevaron cuerpo y `Co-Authored-By`, contra la regla de `procedures/templates/AGENTS.md`, que se había perdido al adaptar el contrato. Restaurada en `AGENTS.md`; desde aquí, una línea y sin trailers. La historia ya mergeada no se reescribe.
- **2026-10-02** — Al preparar el post se vio que la sección "Prior work" del README prometía acreditar código portado de Asegura, pero no se portó nada (la API se escribió desde cero en Fastify). Se corrigió para decir la verdad. Los detalles de la vida de la terapeuta en el post quedan marcados para que el autor los confirme.
- **2026-10-02** — Barrido de los `.md` (PR #16): `plan.md` tenía "CI ⏳" en B1–B2 y "22/22" en B9, y no listaba retención, doble reserva ni el post (ahora B10–B12, con número de PR verificado contra el historial de merges). README con estado y estructura actuales; `verificacion.md` deja de decir que CI está pendiente; `LEARNINGS.md` llena "¿Qué haría distinto?" con lo que pasó de verdad.
- **2026-10-02** — Auditoría completa (PR #17, informe en `docs/auditoria.md`). La más grave: dos mensajes del mismo cuidador en un mismo webhook se procesaban en paralelo y se pisaban el estado. Se reprodujo con un test antes de tocar el código; el invariante nuevo, sin la corrección, encuentra el caso mínimo (dos toques de "Sí, acepto"). También se corrigió el post: en Render la intención la clasifican las reglas, no Gemma.
- **2026-10-03** — B14: la primera compuerta en Windows descubrió dos supuestos de LF: Prettier rechazaba los 127 archivos de un checkout limpio con `core.autocrlf=true`, y el test del front matter no encontraba `tags`. Primero se probó `endOfLine: auto` en Prettier, pero aflojaba la compuerta (aceptaría un archivo CRLF commiteado desde cualquier sistema); se reemplazó por `.gitattributes` con `eol=lf`, que deja el working tree en LF sin importar `core.autocrlf`, y Prettier conserva su `lf` estricto. El test del post además normaliza saltos antes de interpretar Markdown.
- **2026-10-03** — B15: revisión UI/UX completa. La primera propuesta resolvió la jerarquía de Hoy, pero la captura a 360 px descubrió que la píldora de estado comprimía la hora de la visita aunque no hubiera overflow. Se dio al texto una fila propia en móvil y se extendió el sistema visual a progreso, sesión y bóveda; las capturas usan solo datos sintéticos.
- **2026-10-04** — B16: auditoría UI/UX en navegador real (`docs/auditoria.md`). Lo más grave no era visual: cambiar de pestaña a mitad de sesión borraba los ensayos, y "Usar otra bóveda" borraba la bóveda sin preguntar. El fuzz de la ruta tumbó el proceso de Vitest por memoria: `quizPositions` aceptaba una longitud de 1e300. Un primer e2e falló 30/30 porque la pista de la frase de paso estaba dentro del `<label>` y cambiaba el nombre accesible del campo; se movió fuera con `aria-describedby`. Mutaciones: contar sesiones sintéticas y quitar `endSentence` ponen rojo cada una su invariante.
- **2026-10-04** — B16, segunda pasada de bugs (U13–U19). El e2e de "no repetir la celebración" pasó **con** el bug: `toHaveCount(0)` reintenta 5 s y el aviso se cierra solo a los 4 s. Se cambió por una lectura única y la mutación ahora lo pone rojo.
- **2026-10-05** — B17: paleta Terracota, landing en `/`, panel en `/app/`, `vercel.json` y app Expo. Al mover el panel apareció un bug real que dependía de la hora: después de las 7 p. m. en Bogotá la fecha UTC ya es mañana, la última sesión sintética caía en "hoy" y, empatada con la sesión recién grabada, quedaba primero; al volver a la pestaña el borrador SOAP parecía perdido. Se corrigió con fechas locales en los datos sintéticos y desempate por la sesión grabada más reciente. Al incluir `apps/mobile` en el `tsconfig` raíz, los tipos globales de React Native cambiaron `setTimeout` a `number` en la API: el `tsconfig` raíz ahora lista solo `apps/api/src` y `apps/web/src`.
- **2026-10-05** — El autor aclaró que la fonoaudióloga atiende pacientes de **cualquier edad**, no solo niños: la landing y su descripción dejan de decir "niños" e "infantil". El dominio y la app ya hablaban de "paciente" y "familia".
