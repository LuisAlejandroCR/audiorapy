## Challenge Prompt — Build for a Friend

**Build something with open-source AI at its core.**

That can mean running an open-weight model, building on an open-source agent harness or framework, running inference locally, or all three. Whatever you pick, the open pieces should be what makes your project work.

In your post, tell us **why open innovation matters for what you built**. Does it run on a laptop with no internet? Keep someone's data off a server they don't control? Let you fine-tune, swap models, or change how your agent behaves? Cost nothing to run? Tell us where your open-based approach worked better than a closed one.

### This Weekend's Theme: Build for a Friend
**Ship something that solves a real problem for a friend or someone you love.**
Pick one real person and build something for them. It doesn't have to be big. It has to matter to them. Ideas:
- A meal planner that knows your roommate's allergies
- A patient practice partner for a friend learning a new language
- A tool that turns your grandpa's voice memos into a family recipe book

Bonus points if you actually hand it over and tell us what they said.

### Submission template sections (tags: devchallenge, weekendchallenge, hf26challenge)
- What I Built (what does it do, who is the friend, what problem does it solve for them)
- Demo (deployed link or video demo)
- Code (embed GitHub repo)
- How I Built It (which open-source AI: open-weight models, agent harnesses, frameworks, local inference — and how the project is built around it)
- Why Does Open Innovation Matter? (what did it make possible that a closed API wouldn't)
- My Agent Session (optional, judges love it — DevRelay, agent_session tag)
- Prize Categories (list every partner category that applies)
- Team submissions: one member publishes, credits teammates' DEV usernames

**Show your work.** Save your agent session with DevRelay and embed it in your post, or link to it. Optional, but helps judges.

### Judging Criteria

- Relevance to the Prompt and Theme
- Creativity
- Technical Execution
- Use of Partner Technology (optional)

## Prize Categories

### Featured categories ($200 each)
- **Best Use of Render** — Use Render as your project's AI runtime, to host an agent's front end, or to run Hermes or OpenClaw.
- **Best Use of TabPFN** — Use TabPFN, Prior Labs' tabular foundation model, to forecast, predict, classify, or spot anomalies from historical data like a CSV. Use it inside an agent tool (with or without the MCP server) or on its own.
- **Best Use of Tinker** — Use Thinking Machines' Tinker to fine-tune a model for a specific task, and show a clear improvement in performance, latency, or cost over a baseline.
- **Best Use of Arduino** — Build with an Arduino UNO Q: run a model on the board, build a physical agent, or optimize a model with Qualcomm AI Hub.
- **Best Use of DigitalOcean** — Build or deploy on DigitalOcean: host your app or agent, run an open-weight model on a GPU Droplet (1-Click Models), or build an agent on the Gradient AI Platform.
- **Best Use of Gemma** — Use Gemma, Google's open-weight model: run it locally, fine-tune it, or serve it through Google Cloud or another provider.

### Partner categories ($100 each)
- **Best Use of Backboard** — R-CLI open-source terminal coding agent, compare open-weight models through one Backboard API key, or give an OSS project's assistant memory and RAG.
- **Best Use of ElevenLabs** — Give an open-source agent a voice, transcribe audio for a local model, or generate narration for your demo.
- **Best Use of Entire** — Share the agent sessions behind your project in the write-up, or search past agent work to explain why code exists.
- **Best Use of GitHub Copilot** — Copilot coding agent, Copilot CLI, Copilot app, automate with GitHub Actions, or review contributors' PRs with Copilot.
- **Best Use of Mastra** — Orchestrate an agent over open models, add memory and tools to a chat agent, or build a workflow that triages GitHub issues.
- **Best Use of MongoDB Atlas** — Atlas as data layer: Vector Search, long-term agent memory, or the DB behind an app built on an open-weight model.
- **Best Use of Sentry Agent Tracing** — Show your agent's work: setup, performance (latency, tokens, cost), findings, debugging. Include traces/screenshots in the write-up.
- **Best Use of SerpApi** — Live web search for an agent, RAG grounded in fresh results, or news tracking.
- **Best Use of Temporal** — Make your agent durable. Wrap it in a Temporal workflow so it survives failures, retries flaky tool calls, and picks up where it left off.
- **Best Use of Tiger Data** — pgvector embeddings, hybrid keyword+vector search for an agent, or let an agent manage a DB through Tiger MCP.

## FAQ (relevant)
- **PRs don't count** this year; build a brand-new project with open-source AI at its core.
- Five challenges: Weekend (Oct 2–5), then new challenge every Monday (Oct 5, 12, 19, 26). Same prompt, different theme. One submission per challenge; each must be a new project built during that challenge's window.
- One submission can win only once per challenge; automatically in the running for overall + every partner category it qualifies for. Partner tech is not needed to win overall.
- **Can I work on an old project? No — all submissions and their repositories must be started and completed within the challenge window. Commits made after the submission deadline must be noted in the project's README. Failure to do so may result in disqualification.**
- Teams up to 4; one submission per team; list DEV handles.
- **Open source code:** Riffing on open source code and borrowing/improving previous work is encouraged, but changes must be significant. **Any non-generic, non-trivial usage of prior work, including open source code, must be credited in your submission.** Plagiarism → ineligible / disqualification / suspension.
- **Language: Non-English submissions are eligible for a completion badge but NOT eligible for prizes.** Not judged on English mastery.
- **AI use allowed.**
- **Eligibility: 18+.** Official rules: dev.to/page/official-hackathon-rules and dev.to/page/hacktoberfest-weekend-challenge-26-10-01-contest-rules.
- **Judging: "your write-up matters most. A great project with a thin write-up won't win."** Ties broken by judges using the most positive reactions on the DEV post.
- Prizes contacted within 10 business days; winners may need to sign an affidavit and provide tax info (W-9 or similar) within 7 business days.
- Questions: comments on the announcement post, follow #hf26challenge.
